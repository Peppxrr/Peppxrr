I'm not much of a traditional developer. I mostly come up with an idea, beat LLMs over the head with it until something works, and then spend way too long making it actually **good**.

A lot of my projects come from wanting a tool that doesn't exist, or finding an existing one that almost does what I want. I enjoy open-source software, customization, and making things work on **Linux as well as Windows**. The easier it is for people to switch to Linux without giving up useful software, the better.

## 🎮 Featured project: [Shard](https://github.com/Peppxrr/Shard)

**A local-first game clipper and editor for Windows, with experimental Linux support.**

Think instant replay recording, but with a proper editor and control over your own clips. Shard has game capture, separate audio tracks, a clip library, timeline editing, customizable themes, and exports that can target an upload size limit.

No accounts, no cloud requirement, no telemetry. Just your clips on your PC.

## 🤖 The development process, more or less

```text
idea → ask an LLM → discover 12 problems → fix them
     → discover 3 more → finally works → add more features → repeat
```

I might use AI heavily, but I still care about what comes out the other end: software that's useful, reasonably fast, and pleasant to use. If something's broken, I want to understand *why* rather than just call it finished.
